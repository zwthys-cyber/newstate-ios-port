# NSP Pro 0.3.1

独立外置显示工具，面向 iPhone 15 Pro Max / iOS 17.0 / TrollStore，适配 NEW STATE 0.9.98（804）。沿用已有只读采样和跨应用悬浮层，重新设计控制界面。安装包名保持 `NSPExternal.ipa`，Bundle ID 保持 `org.newstateport.External`，覆盖升级保留原有设置。

## 0.3.1 修复

- 默认隐藏已确认队友的全部标记，包含名字、射线、距离、血量和方框；可在显示页关闭「隐藏队友」。本地或目标队伍无法确认时不假定敌我，使用橙色和队伍未知标签。
- 使用 PlayerState 的原生 bIsABot 位显示人机/真人标签；确认的真人敌人使用红色，人机敌人黄色，未知橙色。名称不参与类型推断，分类准确性仍需对局验证。
- 每次采样重新读取 IsDying、队伍、人机标志和血量，不等待元数据缓存。死亡角色不加入/不保留可绘制标记；HP 为 0 但 IsDying 未置位的倒地角色仍保留。状态不可读时不继续绘制该角色旧标记。
- 优先从 GameState.PlayerArray / PlayerState.PawnPrivate 发现角色，每轮最多检查 32 项，仍核对 GUObjectArray 的对象、serial 和销毁标志；此路径不可用时继续全局发现。全局扫描预算从每轮 256 项改为 512 项，调度目标从 30 改为 60 Hz。
- 名字与胶囊元数据缓存从 500 缩短至 250 ms，位置和最终相机仍每轮读取。超过 250 ms 的过期采样结果不绘制，忙碌期间也清掉过期画面。
- 所有类别、信息和射线/方框共用同一距离门槛：相机到目标三维距离严格小于 3000 米；这不是游戏同步距离保证。

本次增加的字段和玩家列表路径来自本地 0.9.98 样本静态分析及合成内存测试，尚未由设备对局确认；理论扫描时间和调度目标不等于实测延迟或帧率。

## 专业版界面

- **总览**：悬浮层启动/停止、游戏读取、屏幕状态文字开关和最近一次采样统计。进程创建、悬浮层响应、等待游戏数据和实际读取分开显示；过期状态不显示为运行中。窗口是否实际可见仍需目视确认。
- **显示**：目标类型、姓名/距离/血量、方框/连线/屏外方向/准星/实验性骨架，按用途分组。新增简洁、均衡、详细三种预设；手动修改后取消预设选中，避免把自定义设置误标为预设。
- **样式**：文字大小 0.8–1.3 倍、显示不透明度 35–100%、线宽 0.6–2.0。设置保存后由悬浮层读取，更新检查间隔约 250 ms。
- **工具**：可选择文字的诊断详情、状态文件导出、手动内存权限验证与发布记录入口。主界面不再堆叠原始诊断日志。
- 深色原生界面、独立图标、Dynamic Type、VoiceOver 标签和 iPad 居中布局。启动期间禁止重复点击，停止操作会取消尚未执行的启动。
- 保留旧版本已知设置；新增样式采用默认值，异常类型使用默认值，数值限制在有效范围内。默认关闭骨架和顶部状态文字。

预设仅改变显示内容，不会开启游戏读取或更改方向、字号、透明度和线宽，均保持骨架关闭：

| 预设 | 主要内容 |
| --- | --- |
| 简洁 | 角色方框、距离、中心准星 |
| 均衡 | 加入姓名、载具和血量条 |
| 详细 | 加入血量数值、连线和屏外方向 |

## 功能与实际边界

用户已确认旧版姓名、距离、人物方框、载具显示可用；截图显示血量条、连线和屏外方向。新增队伍/人机/死亡判断需要实机对局确认；未知类型不冒充已确认真人。血量准确性未独立验证，骨架仍可能有多余分支，物资属于实验性显示。

未实现自瞄、游戏内存修改、后坐力修改、去雾、开发者模式或其他安全检测屏蔽。没有给这些功能添加可用开关。

0.2.6 设备权限实测：辅助程序实际以 root 运行，声明的读取/控制端口权限可在运行时查询到，但对自有子进程和游戏的 `task_for_pid` 均返回 `5`，没有有效控制端口，未尝试写入。验证程序正常退出不代表写入成功。具体拒绝检查不能仅凭该返回码确定。见 [实测记录](../../docs/WRITE-CAPABILITY.zh-CN.md)。0.3.1 保留手动验证工具，不把结果改写成成功。

HUD 仅请求读取端口，目标采样调度为 60 Hz。`performance.read_ms` 是最近一次采样耗时，`sample_interval_ms` 是相邻采样开始间隔；调度目标不等于实际帧率。姓名/胶囊元数据约每 250 ms 刷新，血量、死亡/队伍/人机状态、位置和最终相机每轮读取，不做插值或运动预测。没有游戏数据时不生成模拟人物。

## 安装与使用

1. 在旧版点击停止悬浮层，再使用 **TrollStore** 覆盖安装 `NSPExternal.ipa`。保持开发者模式关闭，不修改原版游戏或注入库。
2. 打开 **NSP Pro**，在「总览」启动悬浮层。若旧进程仍在运行，先停止再启动，确保使用新版。
3. 启动游戏，再回「总览」开启游戏读取，回到游戏目视检查。读取开关与悬浮层启动分别控制。
4. 「隐藏队友」及「真人 / 人机标签」新增默认开启。预设也会开启这两项。在「显示」选预设或逐项调整。升级保留旧设置，所以旧版已开启的骨架、顶部状态文字不会强制关闭；可手动关闭或应用预设。
5. 窗口方向不合适时，在显示页底部选择横屏左、横屏右或竖屏。当前没有自动旋转跟随。
6. 如有异常，到「工具」查看或导出诊断。停止只结束本工具的悬浮进程，不终止游戏；重启手机后需手动启动。

**普通全能签个人/分发证书签名不能授予本工具所需的私有权限。iPhone 17 Pro Max / iOS 26.6 未验证可用，本版不以该设备或签名方式作为支持环境。**

## 诊断与权限

状态目录：`/var/mobile/Library/Application Support/org.newstateport.External/`。

导出包含 `settings.json`、`status.json`、`launch.json`，以及存在时的 `spawn-check-mobile.json`、`spawn-check-root.json`、`memory-check.json` 和 `memory-check-launch.json`。不导出玩家姓名、账号或坐标；镜像定位失败时包含诊断所需虚拟地址，不导出内存内容。查看诊断不会自动上传文件。

控制界面通过 persona 启动独立 root HUD。HUD 使用 `task_read_for_pid` 和 `vm_read_overwrite`，没有控制端口或写入 API。手动 `NSPMemoryCheck` 单独声明 `task_for_pid-allow`、读取和控制端口权限：先尝试自有子进程专用 8 字节的写入/读回/恢复，再仅申请和释放游戏控制端口，不向游戏地址写入。清理超时只终止本工具新创建的 scratch 子进程。

## 构建与验证

所有编译、原生测试、图标生成、签名检查和模拟器 UI 检查均在 GitHub Actions 的 macOS 运行器执行。模拟器构建单独使用隔离的临时目录，不运行 HUD/root helper，不读取游戏，也不放入发布的设备 IPA。UI 检查覆盖配色、未知分类标签、默认队友过滤、预设、持久化、旧设置迁移、数值范围、状态语义、启动取消、三个页面的滚动布局，并在普通和辅助功能大字号下执行。发布预览来自实际 UIKit 模拟器截图，无游戏数据。

CI 检查四个设备程序的 arm64 / iOS 17 目标、逐页代码签名、权限、依赖、图标和 IPA 完整性；既有采样和镜像解析测试继续执行。模拟器通过不代表 iOS 17 真机悬浮层、游戏读取或内存写入验证通过。

公开源码和产物不含游戏程序、个人证书或设备原始日志。HUD 启动和窗口托管参考 Lessica/TrollSpeed（MIT），完整许可见 `ThirdPartyNotices.txt`。
