# NEW STATE iOS port

目标游戏：NEW STATE 0.9.98 (804)，com.pubg.newstate，ARM64。

当前方案是 TrollStore 独立外置 IPA，设备为 iPhone 15 Pro Max / iOS 17.0，开发者模式关闭，游戏文件保持原样。用户已在 0.2.4 确认人物姓名、距离、方框及载具标记/距离可见。0.2.5 增加采样延迟优化、血量条和屏外方向提示，尚待对应版本实机复测。当前安装与范围见 [独立 IPA 说明](apps/ExternalPort/README.zh-CN.md)。

下方保留先前 iOS 26.6 / 全能签及动态库注入的排查历史，不是当前推荐安装流程。SDK、最低部署系统、用户设备系统和各功能验证状态分别记录；历史尚未验证的结论不能代替后续独立 IPA 的实机结果。

状态：0.1.0 收到“启动即退、未见 NSP”的设备反馈，原因尚未确定。0.1.1 调整启动时序并提供独立加载对照库，仍待设备复测。Android APK 为 PUBG Mobile 外部工具，原生 ELF 不能直接作为 iOS dylib 使用；本仓库针对上传的 iOS 主程序重新实现数据读取。

本仓库仅包含原创移植代码、构建脚本和分析结论；不包含游戏主程序、框架、APK、游戏资源或设备日志。编译与原生测试使用 GitHub 托管 macOS 运行器。CI 通过不代表实机功能已验证。

## 当前设备测试条件与只读版注入包

用户最新确认：开发者模式关闭时游戏可正常打开；开启时出现安全提示网页。后续测试保持开发者模式关闭，不将开启开发者模式作为插件测试条件。此设备对照仍需与注入状态分开记录，不能把通用提示中的应用举例当作实际命中清单。

**NewStatePort-InjectorSign.dylib** 是现有 0.1.2 只读显示版的无预签名包装，编译代码保持不变，让 TrollFools 执行其签名流程。不包含开发者模式或其他安全检测屏蔽功能；此前最小库的实际导出件采用该路径后，9 个 SHA-256 签名页全部匹配。最小库的结果不能替代此显示库的实机验证。

用 TrollFools 移除旧测试库，保持开发者模式关闭，确认游戏恢复正常后，仅注入 NewStatePort-InjectorSign.dylib。前台等待至少十秒检查 NSP；显示采样默认关闭。出现 NSP 后再手动开启只读显示，骨架先保持关闭。没有 NSP 时检查 Documents/NewStatePort/load.log，其中 no active UIWindowScene 表示尚未匹配窗口安装路径；当前版本没有单独为旧式无 UIWindowScene 的应用实现窗口兼容路径。若游戏退出，先记录是否出现网页或新 ips，并导出手机上实际处理后的同名库。

此包不要求预先用全能签重签，不与其他 Probe/Trace/Port 同时加载。它仍是未实机验证的实验性只读显示版，自瞄、后坐力修改、去雾尚未实现。

## 启动阶段日志库

无预签名最小库的设备导出件现已检查：4 KB/9 个实际 SHA-256 页全部匹配，之前的分页不一致在该文件中已消除。但用户仍报告启动即退、没有游戏画面，本轮未生成 ips。这不能直接证明游戏主动退出，也不能证明 CMS 信任或整个加载过程通过。

**NewStateStartupTrace-InjectorSign.dylib** 是独立诊断库，默认不携带预签名，需注入器签名。它仅通过 libSystem 写四个阶段：`constructor`、`main_queue`、`alive_3s`、`alive_10s`。没有游戏内存读取、函数挂钩、UIKit、退出拦截或检测结果修改。每行包含库版本、PID、单调时钟与阶段，不记录账号、玩家数据或设备标识。

日志尝试写到游戏数据容器两个位置：

- `Documents/NewStatePort/startup-trace.log`
- `tmp/NewStatePort-startup-trace.log`（根据进程 TMPDIR；若该环境变量缺失则不写此副本）

使用：确认未注入可启动；移除先前的库，仅注入此文件。测试一次后导出任一日志，以及注入器处理后的同名 dylib；若无日志，直接反馈“两个位置都没有日志”。日志只有 PID 不同的记录时，以本轮 PID 为准。它不创建 NSP，不开启或关闭开发者模式。若无日志，可能是未执行到构造函数、目录或环境变量不可用、写入失败或其他原因，不能只据此认定未加载。若只有 constructor，说明初始化函数开始执行，但不能推断退出函数来源。若有 main_queue，说明主队列回调执行过；时间戳仅说明回调执行时间，不是精确退出时间。诊断库的文件 I/O 与排队本身会改变进程行为，结果仅用于缩小范围。

## 独立签名路径排查版

0.1.2 实机复测仍然退出。手机导出的最小库又是 16 KB/3 个 SHA-256 页，三个哈希均不匹配；发布的原库是 4 KB/9 页并且全部匹配。因此发布时指定分页未解决注入后的签名异常，不能称为修复完成。

新增 **NewStateLoadProbe-InjectorSign.dylib**，它与已编译最小库的 `__text` 完全一致，但由 Apple codesign 移除预签名，不携带 LC_CODE_SIGNATURE。TrollFools 的公开源码会对没有签名命令的输入先执行 `ldid -S`，此变体用于区分“重用输入签名”与“注入器生成签名”两条处理路径。公开源码不代表用户设备所用的辅助工具二进制完全相同，仍需设备验证；这个包不是对注入器签名工具的补丁。

此文件不能直接加载，必须由支持未签名输入的注入器签名后使用。只供 iOS 17.0 / TrollFools 排查，不能拿去与已签名库同时注入。它没有界面、没有日志、没有游戏读取。恢复设备工具可用后，先移除旧注入并确认游戏原本能启动，再单独测试它。如果还退出，检查新的 ips 与注入后导出的同名文件，不能用构建检查代替设备签名验证。

## 0.1.2：TrollFools 签名分页兼容

iPhone 15 Pro Max / iOS 17.0 / TrollFools 4.2（227）测试最小库后出现 `CODESIGNING / Invalid Page`。设备导出的最小库 SHA-256 CodeDirectory 声明页大小 16384 字节，但三个哈希均对应按 4096 字节切分的数据，按声明的 16384 字节校验全部失败。这是注入产物中可复现的签名不一致；崩溃日志没有模块列表，仍需实机复测确认因果。

0.1.2 构建时显式使用 4096 字节签名页。产物检查不再只确认签名存在，还要求页大小、页数、覆盖范围及每页 SHA-256 均正确，并验证篡改一个代码页后检查必然失败。这个 4 KB 是代码签名分页大小，不是设备的虚拟内存页大小。设备系统的内存页大小不需要更改。

设备上传的 `.app` 中主程序为未修改的加密原版，插件通过 `newstatex` 框架加载，与另行上传的解密 IPA 是两份不同输入。框架中的辅助签名目录不能单凭普通哈希不匹配判定失败；本次异常发生在最小库实际内容对应的 SHA-256 目录。游戏文件、设备文件与签名材料不进入公开仓库。

请先用 TrollFools 移除旧注入、确认恢复启动，再单独注入 **0.1.2 的 NewStateLoadProbe.dylib**。它不显示界面。正常后移除它，再测试同版本 NewStatePort.dylib。不要同时加入两个库。尚未实机验证，不能承诺其他签名或游戏运行问题已经解决。

## 0.1.1 启动排查

0.1.1 的构造函数只向主队列派发任务；NSBundle、UIDevice、日志和目标校验均延迟执行。界面等待应用连续激活十秒才安装，读取器直到手动开启才创建。启动阶段写入 `Documents/NewStatePort/load.log`；没有日志不能单独证明插件未加载或游戏保护触发。

本次同时构建两个互斥测试库：

- `NewStatePort.dylib`：延迟启动的只读显示版。
- `NewStateLoadProbe.dylib`：最小加载对照版，仅在构造函数设置自身的一个整数；不链接 Foundation/UIKit，不创建界面、不写日志、不读取游戏。正常时不会出现 NSP。

每次从同一份干净 IPA 开始，只注入一个库，不能覆盖安装在已有插件的 IPA 上：

1. 先确认不加任何插件、只重签的 IPA 能否启动。如果也退出，先排查安装包或签名；不要据此判断显示插件崩溃。
2. 若基线正常，仅注入 `NewStateLoadProbe.dylib` 重签测试。若仍退出，说明问题可在没有界面/采样代码时发生，需要设备 `.ips`、签名与加载信息进一步定位，不能直接认定是保护检测。
3. 若对照版正常，重新用干净 IPA 仅加入 `NewStatePort.dylib`。前台保持至少十秒，检查 NSP 和阶段日志。
4. 若仍退出，从 iOS“设置 → 隐私与安全性 → 分析与改进 → 分析数据”查找对应时间的 ExtremeGame／NEW STATE `.ips`。若生成 `load.log`，一并提供。设备日志不要提交到公开仓库。

这些改动是风险收敛与诊断措施，尚无证据证明已修复用户此次闪退。构建与静态检查不能验证游戏实机启动。

## 显示功能范围

已编写角色位置、血量、姓名、距离、基于胶囊高度的方框、连线、中心准星、实验性骨架，以及部分载具和物资组的位置标记。骨架默认关闭，使用参考骨骼父子关系、当前组件空间姿态及组件到世界变换，覆盖自身姿态缓冲和有效的 leader-pose 重映射路径。姓名读取不覆盖游戏自定义虚拟返回路径，无法确认时使用“角色”标签。角色标记包含队友，未实现队伍区分；物资组标记不是组内逐件物品识别。方框为胶囊投影，不是骨骼包围框。

尚未实现自瞄、后坐力修改、去雾等功能。未提供反检测功能，也未验证重签后的游戏能够正常启动。所有显示功能均等待实机验证。原 APK 全部菜单的迁移状态见 [功能清单](docs/FEATURE-MATRIX.zh-CN.md)。

读取只发生在游戏进程内，通过 iPhoneOS SDK 提供的 vm_read_overwrite 读取自身内存；不申请其他进程权限，不依赖 TrollStore、越狱路径、Substrate 或第三方挂钩库。没有调用游戏函数、修改游戏内存、执行 APK 中的脚本。此阶段先验证 iOS 对象及相机读取链，不能把 CI 成功当作全功能移植完成。

## 全能签安装与验证

1. 从成功的 GitHub Actions 构建中下载 `NewStatePort.dylib`。
2. 在全能签导入目标版本 IPA，使用其添加／注入动态库功能加入 dylib，然后重签、安装。保持 Bundle ID 为 `com.pubg.newstate`。仅把 dylib 复制到手机不会自动加载。不要同时加入旧诊断插件，以免难以区分结果。
3. 进入游戏并在前台等待至少十秒后，点击左上角 `NSP`，开启“只读显示”。初次对象扫描需要时间，界面显示扫描进度；进入对局后检查位置、血量和显示对齐。
4. 菜单的“导出当前状态”生成 JSON，只包含版本、读取阶段和计数，不包含玩家姓名、账号或位置。如果没有按钮或游戏提前退出，可检查游戏数据容器 `Documents/NewStatePort/load.log` 是否生成。

已解密主程序、原版、Info.plist 和 Frameworks.zip 仍保留在本地，不进入公开仓库或构建输入。本仓库不生成包含游戏内容的 IPA。全能签需要使用用户自己的安装包和签名方式。

## GitHub 编译与检查

推送 main 或手动运行 `Build iOS plugin`。编译与原生测试限 GitHub 托管 macOS 26，使用 Xcode 26.6；源码服务器不编译原生目标。SDK 版本以产物 `build-info.json` 为准。

CI 执行带 AddressSanitizer / UndefinedBehaviorSanitizer 的主机逻辑测试，然后通过 Apple iPhoneOS SDK 编译 ARM64 dylib、进行临时签名，并核实 Mach-O 类型、iOS 平台、最低系统、初始化入口、安装名和系统依赖。产物包含 dylib、测试记录、签名记录、构建来源、源码 ZIP 和 SHA-256。

主机测试覆盖解码向量、相机投影、异常输入、弱引用的序列号/销毁标记/边界以及类型继承与不可读内存，并用人工内存模型验证完整世界/控制器/相机/标记流程和失效处理。骨架测试覆盖缩放、四元数旋转、父索引、缓冲索引和 leader-pose 重映射。人工模型不证明实际游戏布局正确。测试不运行游戏、不模拟反作弊，也不覆盖实机加载与显示效果。
