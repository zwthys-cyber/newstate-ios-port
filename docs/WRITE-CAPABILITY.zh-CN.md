# 自瞄与内存写入的当前限制

更新：0.2.6 增加手动运行的 NSPMemoryCheck。该辅助程序明确请求控制端口权限，计划测试自有子进程专用 8 字节内存的写入/读回/恢复，再单独请求游戏控制端口（不写游戏）。当前 HUD 仍只读，测试部署时不执行开发者模式切换。

用户已提供 0.2.6 的设备实测结果：辅助程序 UID/EUID 均为 0，运行时能查询到声明的读取、控制端口及 `task_for_pid-allow` 权限；但自有 scratch 子进程和游戏的 `task_for_pid` 均返回 `5`，均未取得有效端口，两处 `write_attempted` 均为 `false`，`game_memory_written` 为 `false`。因此本次没有执行跨进程写入，当前测试的控制端口路线未打通。返回码本身不足以定位具体拒绝检查，不能仅据此断言是开发者模式导致。

配套启动记录显示 `spawn_return: 0`、`exit_code: 0`、`wait_status: 0`。这只确认验证程序已启动并正常退出；结果中的 `stage: completed` 也只表示验证流程完成，不表示取得控制端口或写入成功。自有 scratch 子进程正常退出同样不能作为写入成功的证据。本记录仅归纳结果，不公开原始设备日志或进程标识。

当前已验证的运行条件是：iPhone 15 Pro Max / iOS 17.0、TrollStore 独立外置程序、开发者模式关闭、不向游戏注入、不改动游戏 IPA。用户已确认 0.2.4 的人物姓名、距离、方框和载具显示。以上结果证明部分读取与绘制路径可用，不证明已经取得游戏写入权限。

HUD 使用 `task_read_for_pid` 取得读取端口。Apple 的 `mach_vm.defs` 把读取接口的参数声明为 `vm_map_read_t`，写入接口则要求 `vm_map_t`，二者不能互换。`ipc_tt.c` 的任务端口转换检查还规定：开发者模式关闭时，拒绝其他活跃任务的控制端口转换；该检查位于 root/内核等后续例外判断之前。额外声明一个权限或以 UID 0 运行，不能据此跳过该条件。

- [iOS 17 XNU：任务控制端口与开发者模式](https://github.com/apple-oss-distributions/xnu/blob/xnu-10002.1.13/osfmk/kern/ipc_tt.c#L2307)
- [iOS 17 XNU：读写 VM 接口类型](https://github.com/apple-oss-distributions/xnu/blob/xnu-10002.1.13/osfmk/mach/mach_vm.defs#L198)

因此当前外置架构没有经验证可用的游戏写入通道；内存自瞄、后坐力修改、游戏 FOV 修改等尚未接入。这里只说明当前实现与运行条件的限制，不声称其他架构在所有环境都不可能实现。

自瞄还有独立的数据依赖：可靠的敌我判断、目标部位、开镜/开火条件及失效目标处理。0.3.1 已按登记字段接入队伍和人机分类，但仍需实机验证，未知分类不当作已确认敌方目标；显示数据不能直接等同于可自动操控的目标。屏外方向箭头、血量条或准星提示属于显示功能，不等同于自动瞄准。

此记录不包含开发者模式自动开关、内核修改、游戏检测屏蔽，也没有新增未生效的自瞄/写入菜单开关。当前继续提供只读显示；各项显示准确性与持续采样性能需分别实机验证。
