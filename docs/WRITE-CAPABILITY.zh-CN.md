# 自瞄与内存写入的当前限制

更新：0.2.6 增加手动运行的 NSPMemoryCheck。该辅助程序明确请求控制端口权限，测试自有子进程专用 8 字节内存的写入/读回/恢复，再单独请求游戏控制端口（不写游戏）。当前 HUD 仍只读；设备上的实际能力等待导出结果，本文的内核分析不代替该实测。测试部署时不执行开发者模式切换。

当前已验证的运行条件是：iPhone 15 Pro Max / iOS 17.0、TrollStore 独立外置程序、开发者模式关闭、不向游戏注入、不改动游戏 IPA。用户已确认 0.2.4 的人物姓名、距离、方框和载具显示。以上结果证明部分读取与绘制路径可用，不证明已经取得游戏写入权限。

HUD 使用 `task_read_for_pid` 取得读取端口。Apple 的 `mach_vm.defs` 把读取接口的参数声明为 `vm_map_read_t`，写入接口则要求 `vm_map_t`，二者不能互换。`ipc_tt.c` 的任务端口转换检查还规定：开发者模式关闭时，拒绝其他活跃任务的控制端口转换；该检查位于 root/内核等后续例外判断之前。额外声明一个权限或以 UID 0 运行，不能据此跳过该条件。

来源：

- [iOS 17 XNU：任务控制端口与开发者模式](https://github.com/apple-oss-distributions/xnu/blob/xnu-10002.1.13/osfmk/kern/ipc_tt.c#L2307)
- [iOS 17 XNU：读写 VM 接口类型](https://github.com/apple-oss-distributions/xnu/blob/xnu-10002.1.13/osfmk/mach/mach_vm.defs#L198)

因此当前外置架构没有经验证可用的游戏写入通道；内存自瞄、后坐力修改、游戏 FOV 修改等尚未接入。这里只说明当前实现与运行条件的限制，不声称其他架构在所有环境都不可能实现。

自瞄还有独立的数据依赖：可靠的敌我判断、目标部位、开镜/开火条件及失效目标处理。当前角色标记包含队友，不能把已显示人物的位置直接当作可自动操控的敌方目标。屏外方向箭头、血量条或准星提示属于显示功能，不等同于自动瞄准。

此记录不包含开发者模式自动开关、内核修改、游戏检测屏蔽，也没有新增未生效的自瞄/写入菜单开关。0.2.5 仍先交付只读显示和延迟优化，新增显示功能与实际性能需实机复测。
